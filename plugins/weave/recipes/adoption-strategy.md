# Recipe: adoption-strategy

Adoption strategy document on the document template: the plan for getting
an organization to actually use something Microsoft is rolling out. This is
one of three independent adoption recipes (`adoption-strategy`,
`adoption-comms`, `adoption-training`) -- pick the one the request actually
needs, not all three at once.

## What each section says

- **Current State**: today's usage or awareness level, stated plainly. If
  the source gives a number (licenses assigned, active users, a survey
  score), use it. If it only gives a qualitative read ("most people haven't
  touched it yet", "IT champions are using it, nobody else"), say that
  instead. Never fabricate an adoption percentage to make this section look
  more precise than the source supports.
- **Adoption Goals**: specific and measurable -- "60% of frontline staff
  using Copilot weekly by end of Q1", not "improve adoption." A goal with no
  number or date is a goal that can't be checked later; if the source
  hasn't set one, flag it rather than inventing a target.
- **Approach**: the actual tactics being used to get there -- champions
  network, training waves, comms campaign, incentives, executive
  sponsorship. Name them specifically; "drive adoption through
  communication and training" restates the section heading and says
  nothing.
- **Success Metrics**: things that can actually be measured -- usage
  percentage, survey score, ticket volume, license utilization. Not vague
  aspirations ("people feel confident using the tool"). If a metric has no
  measurement mechanism behind it, either name how it will be measured or
  flag the gap.
- **Timeline** (optional): phases the rollout (e.g. pilot, wave 1, wave 2,
  steady state) with rough dates. Drop the section if the source has no
  phasing to report rather than inventing one.

## Asking for what's missing

Only `initiative` is required and usually isn't inferable from a generic
source -- ask for it in one question if the source doesn't name what's
being adopted.

## Hard rules specific to this recipe

- Never invent a baseline adoption number, a target percentage, or a
  timeline the source doesn't support. A missing baseline is
  `[TO BE PROVIDED]` in prose, not a guessed figure.
- Approach and Success Metrics must stay distinct: tactics go in Approach,
  measurements go in Success Metrics. Do not let a tactic ("run a lunch and
  learn") stand in for a metric.
